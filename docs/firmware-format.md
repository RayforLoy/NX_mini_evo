范围：仅验证 NXMINI／01.10／GLUAOA2，构建时间 `201501162119`。已知校验有效表示离线结构与加法校验通过，不能表示机身认可或可恢复。

资源头 32 字节，条目数位于头内 `+20`。每个条目为 56 字节名称、LE32 相对偏移、LE32 长度；相对偏移从整个目录末尾算起。解析器拒绝越界、资源重叠、重复名称及不安全路径。

官方包含以空格结尾的资源名，例如 `BS_SHT_Conti_6fps.wav `。提取文件使用百分号转义后的 `BS_SHT_Conti_6fps.wav%20`，清单同时保留原名 `name` 与磁盘名 `extracted_name`，重组时不会更改原目录名称。末尾点和 Windows 保留名称也做可逆转义。

## RELC 编码

实现参考公开的 [M7MU 压缩格式](https://github.com/ge0rg/samsung-nx-hacks/wiki/M7MU-Compression)，独立编写编解码器，并与独立解码结果的哈希交叉核对。

- 每块有大端 16 位头，`0x0000` 为整个流结束。高位为 1 时是原样数据，低 15 位为长度，`0x8000` 表示 32,768 字节。
- 压缩块的头是压缩负载字节数。负载用大端 16 位标志组，最高位先读：0 为一个字面字节，1 为双字节回溯令牌。
- 距离为 `(第一个字节 >> 3) * 256 + 第二个字节`，范围 1..8191；长度为 `(第一个字节 & 7) + 3`。初始长度为 10 时，继续累加扩展字节，255 表示还有扩展。
- 双零令牌结束当前压缩块，必须准确落在块末尾。重叠拷贝与跨块历史均保留。
- 首块解压上限 32,768 字节，其后每块 24,576 字节；总解压量有配置上限。

独立 `encode` 不保证复制原压缩器的令牌选择。`repack` 保留无修改块，仅重编码内容或历史发生变化的块，所以无修改重组能够逐字节一致。代码长度调整和段搬移尚未支持。

## 已确认校验

`code_end = code_offset + code_size`：

```text
code_checksum = -sum(LE16 words in [code_offset, code_end - 2)) mod 2^16
write LE16 at code_end - 2
sum(LE16 words in [code_offset, code_end)) mod 2^16 == 0

footer_offset = file_size - 20
file_checksum = sum(LE32 words in [0, footer_offset)) mod 2^32
footer[0:4] = LE32(file_checksum)
footer[4:8] = LE32(footer_offset)
```

官方代码校验为 `0x08ed`，整包加法校验为 `0xcf1275c0`。Ghidra 静态路径分别对应 `0x40093820 / 0x40093c04` 和 `0x40091f98`，地址以解压段 1 映射 `0x40000000` 为前提。

尾部剩余 12 字节固定为 `fc0000000000000000000000`，含义未还原。工具保留它并检查与基线布局一致，不声称已理解这些字段或全部升级条件。这两项加法校验也不是数字签名。

## 重组与补丁

提取保留 `original.bin`、头部、writer、压缩段、解压段和资源。只编辑解压段与同长度资源；writer 和头部直接修改会被拒绝。修改段必须装入原分配空间，增长只能使用已确认全零的对齐填充；后续段和资源不能移动。修改后重算校验、重新解析并解压全部代码段。

补丁清单的可用结构如下。示例故意没有字节操作，运行会被拒绝，避免把演示改动当成镜头补丁：

```json
{
  "schema_version": 1,
  "model": "NXMINI",
  "version": "01.10",
  "input_sha256": "8a5bbe8885df239739f85f92087fea3972c05f98bd6521d809ed60dd5aca89fa",
  "operations": []
}
```

真实操作需要 `space`、`offset`、`before`、`after`，并指定 `section` 编号或 `resource` 名称。偏移为该解压段／资源内偏移；十六进制原字节与新字节必须同长，禁止重叠。可选 `output_sha256` 绑定输出。执行方式：

```powershell
.\.venv\Scripts\python.exe -m nxmini patch data/firmware/DATANXmini.bin verified-patch.json work/candidate.bin
```

回执始终记录输入／输出哈希及 `flash_ready: false`。固定长度资源补丁在提供输出哈希后可 `--reverse`；压缩代码回滚使用保存的、哈希正确的官方原件，不能假定再次压缩恢复相同字节。`patches/research-targets.json` 是研究目标清单，没有可应用操作。
