# C01：手动镜头放行离线候选

此候选针对官方 NX mini 1.10，修改真实 ARM 拍摄事件路径。**尚未验证机身启动、无短接成像、曝光或恢复，不可作为可刷发布版。**

固件：`dist/nxmini-evo-C01/manual-lens-C01_OFFLINE_ONLY.bin`，135,010,548 字节。

```text
原件 SHA-256
8a5bbe8885df239739f85f92087fea3972c05f98bd6521d809ed60dd5aca89fa
候选 SHA-256
70e65194c5130e365bcd110866532d4dc7954a50641867265263cea0d222a5f3
```

## 修改及依据

清单：`patches/manual-lens-c01.json`。所有地址为段 1 解压后加载到 `0x40000000` 的静态分析地址，实际运行映射尚未实机确认。

| 地址 | 修改 | 作用范围 |
| --- | --- | --- |
| `0x4014dcc8` | `bne 0x4014dd30` → `mov r0, r0` | `onEventKeyS2` 不再仅因镜头脱离就转入拦截；之后独立的镜头故障查询仍执行 |
| `0x406c7ee8` | `tst r0,#0x40000000` → `movs r0,#1` | 镜头事件 2 走原厂 `nolens on` 对应路径 |
| `0x406c7fd0` | 同上 | 拍摄结束处调用的镜头事件 6 走同一策略，避开无镜头弹窗路径 |

这三处不修改镜头脱离标志，不伪造电子镜头信息，也不持久写 EEPROM。共享状态 `+0x28` 的 bit 4 仍可由原始函数读出。此候选没有合入此前的非 XM 闪光资格实验。

原厂 `nolens on` 调试开关本身没有覆盖第一处全按分支，不能仅通过启用该开关宣称免短接拍摄已经完成。

## 离线验证结果与边界

`tools/verify_candidate.py` 独立于补丁写入器，逐段解压候选并与清单比较；全部 7 段恰好匹配预期改动，163 个资源、writer、未解释尾部字节及其他未授权区域均未变化。已知两层加法校验有效，段位置和文件长度保持原布局。

候选只改动 3 条指令。原压缩段重新编码会连带改变压缩字节及校验值，不能把整个文件的二进制差异直接当作指令改动数量。保留有效原压缩 token 的策略使段 1 只增加 7 字节，位于原有 404 字节分配余量内；没有移动后续段。

原始 ARM 指令的受控执行覆盖 6 个模式值、连接／未连接状态，共 12 组全按路径：未连接时从镜头拦截转至原始 `startS2Mode` 回调 `0x4014eb60`；连接时路径与原件一致。原始模式虚表及准备状态判断 `0x4027bde0` 同时执行，没有把它们替换成固定“允许拍摄”。其他镜头故障及未准备就绪的条件另有回归测试。事件 2、6 的候选结果与原件启用 `nolens` 标志的结果相同。

这些探针使用合成 RAM（共享状态 `+4=0x80000`、全按前 `+8=0xc`、`+0x330=1`），显式建模相机 `+0x34` 查询、计时状态、取消半按、日志和 UI 清理；在 `startS2Mode` 回调入口停止。部分已连接镜头路径在电子镜头查询边界停止。没有模拟 REALOS、自动曝光、ISP、传感器、闪光充电或完整拍摄，因此不能把它们当作机身拍摄验证。

验证记录修订：最初探针将 `0x4044463c` 标为拍摄 API，复核日志发现它实际是 `doHalfShutterCancel`，该标记已纠正。现用原厂模式虚表（Program `0x40770f10`、ASM `0x4076abd4`、SmartAuto `0x4077452c`、SelfShot `0x407728d4`）追到共享 `+0xe8` 的 `startS2Mode`；其日志名称指针 `0x4014ee18 → 0x40739571` 已核对。该入口也不能等同于物理拍摄 API。二进制修改和候选哈希未变；仅验证记录及工具已修正。

| 功能 | 当前结论 |
| --- | --- |
| 手动镜头免短接 | 已有针对普通全按及事件拦截的真实候选；机身出片待验证 |
| Smart Auto | 模式值 `0x2002` 下的无镜头全按路径已通过受控探针；曝光正确性待验证 |
| 自拍内闪 | 未修复，C01 不修改闪光配置／权限／下发函数 |
| 原厂 9mm | 已连接分支的局部路径一致；完整回归待验证 |
| 工厂实验菜单、无线、滤镜 | C01 未实现这些机内功能 |

已知未覆盖状态：准备判断 `0x4027bde0` 在共享状态 `+4` 的 `0x400000` 位为 1 时，仍有自己的镜头脱离分支（`0x4027be18`）。C01 没有修改它；上表中的成功路径输入没有设置该位。该状态的实际触发条件和手动镜头半按过程需要继续追踪，因此 C01 不能被称为完整免短接修复。

## 实机验证条件与顺序

刷写条件仍未满足：需要确认机身备份范围、实际恢复入口和断电恢复路径；这份文档不提供未经验证的刷写／降级步骤。只有在这些条件确认后，才进入以下实测。

1. 原厂 9mm：开机、半按／全按、存片、回放、连拍、关机，并记录 LCD 错误或卡死。
2. 无触点转接环、触点完全不短接：P／A／S／M 各拍一张，检查 SRW／JPEG、连续拍摄及每次存片后的弹窗。
3. Smart Auto：固定手动镜头光圈，用不同亮度场景比较快门、ISO、直方图及实际曝光；不能用“快门能按”替代测光验收。
4. 镜头切换：断电后换原厂／手动镜头，分别测试启动；有条件再按原厂允许的流程测试开机换镜。
5. 自拍：翻屏进入／退出、倒计时和原厂镜头回归。内闪问题单独记录，C01 不以此项通过为交付声明。

回退依据是上述哈希正确的官方原件。重新刷回原件和故障恢复的实际步骤尚未验证，不能把保留原件等同于已具备恢复能力。
