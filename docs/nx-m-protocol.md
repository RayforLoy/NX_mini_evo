# NX-M 卡口协议文档：证据草案 v0.1

目标是将其他系统镜头装到 NX mini。本文目前不能用于按针脚接线或发送电子命令：没有卡口引出和实测波形，电气协议仍未知。普通 NX 卡口资料只作为研究线索，不能代替 NX-M 验证。

## 证据等级与当前结果

“实测”必须有原始照片／尺寸记录／波形及设备信息；“静态推断”来自 1.10 固件；“未知”表示尚无可用证据。当前没有已验证的电子命令。

| 项目 | 当前值／结论 | 等级与依据 |
| --- | --- | --- |
| 机身／镜头 | NX mini／原厂 NX-M 9mm | 用户提供，未接机读出 |
| 机械尺寸、定位面、锁止角 | 未测量 | 未知；需卡尺／深度计与照片 |

## 被动抓取方法

先制作保持原始电气连通的引出结构，记录厚度、触点位置和插接方向。使用高输入阻抗、与实测电平匹配的探测设备；在确认地和供电前不连接未知信号或向触点供电。不要用逻辑分析仪的数字阈值代替电平测量。

每次操作仅改变一个变量。建议捕获序列：关机→开机、开机后空闲、半按／全按、各档光圈、AF 近远、录像进入退出、休眠唤醒、关机。9mm 定焦可以研究光圈和 AF；无法凭该镜头证明所有 OIS／变焦行为。镜头或机身固件版本变化要分别记录。

触点先用 `P01`、`P02` 等中性编号，并附“从机身正面看、定位点方向”的照片；抓取通道叫 CH0／CH1，不在没有证据时命名 CLK／MOSI。先测量空闲电平、方向及时间关系，再选择解码器，记录每个参数及误码情况。

目录建议：`work/captures/CAP-0001/`，保存原始工程、未裁剪波形、CSV、照片、操作日志和 `manifest.json`。模板在 `research/templates/capture-manifest.json`；原始文件需计算 SHA-256，后续每条协议结论引用捕获 ID 和时间范围。

## 已提供的时序工具

```powershell
.\.venv\Scripts\python.exe -m nxmini trace work/captures/CAP-0001/digital.csv --time-column 'Time [s]' --json work/captures/CAP-0001/timing.json
```

CSV 示例：

```csv
Time [s],CH0,CH1
0.000000,0,1
0.000001,1,1
0.000002,0,1
```

工具统计各通道跳变数、最小／中位边沿间隔，检查时间单调和二值输入；输出协议仍为 `unidentified`。统计值不是自动识别波特率的结果，更不是实测卡口参数。

## 命令记录接口

将命令证据写入 `research/protocol/commands.json`。记录方向、请求／响应字节、时序、单位、前置状态、可重复性、失败行为、原始波形引用和解释等级。下列字段未知时保留 null，不填造示例命令：

```json
{
  "id": "pending-aperture-command",
  "status": "unknown",
  "request_hex": null,
  "response_hex": null,
  "capture_ids": [],
  "timing_range_s": null,
  "verified_on_camera": false
}
```

只有重复捕获对应同一操作、字节语义与响应均解释清楚，并经过受控原厂镜头回放验证后，才把命令标记为“实测”。制作电子转接环前还要验证上电顺序、驱动方向、检测保护、异常超时和失联时的机身处理。
